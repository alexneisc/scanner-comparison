Entrance scanner: Tauri or native Swift

Test on one iPhone 14 Pro (iOS 27.0.1). Camera scanning of QR codes and barcodes. The numbers were collected by hand, not on a lab setup.

Source code: Tauri version (scanner-proto) · Swift version (scanner-swift)

Summary

  • Scan speed is the same. Both apps use the same iOS camera API. Medians differ by less than 10 ms.
  • Swift uses 3–5 times less memory. Idle: about 14 MiB vs about 50 MiB. Peak during scanning: about 19 MiB vs about 98 MiB. Most of the Tauri memory is the WebView process.
  • Swift uses about half the CPU time per scan. About 60 ms vs about 116 ms.
  • Close focus needs extra camera setup in both apps. In Swift it is a few lines in the app code. In Tauri the official plugin does not allow it, so we had to patch the plugin's own Swift code.
  • The flash is needed in the dark. In strong darkness neither app reads a code; with the flash on, scanning works. In Swift the flash is a few lines in the app code. In Tauri the plugin has no flash, a separate flash plugin froze the camera, so this also needed a plugin patch.
  • Cost of the Tauri route: a local fork of the scanner plugin that has to be kept in sync with every plugin update. Android was not tested and would need its own changes.

The close-focus problem

A guide holds the phone close to the ticket, often 5–10 cm. Small codes have to be this close, otherwise the camera does not see enough detail.

The main camera lens of the iPhone 14 Pro cannot focus that close. Its minimum focus distance is roughly 15–20 cm. Closer than that the image stays blurry and the code is never read.

The phone can focus much closer, but only through its ultra-wide lens (macro). The system Camera app switches to that lens automatically. A scanning app gets this only if it asks iOS for the combined multi-lens camera instead of the main lens. Then iOS switches lenses by itself when the code comes close; on screen this looks like a jump in the picture.

What we saw: without this setup, both a native Swift app and the official Tauri plugin failed to read a small QR code at close range. With it, both read it. Switching lenses costs time: a small code at 10 cm takes about 1,8 s, a large code at the same distance about 0,5 s.

Phones without an ultra-wide lens (for example iPhone SE) probably cannot focus this close at all. Not tested.

Plugin patch (Tauri)

The patch has two parts. Both changes are made in a local copy of the plugin (the vendor folder), in the Swift code for iOS.

  1. Focus at close range. The official plugin opens the main lens, which cannot focus close (see "The close-focus problem"). The patch selects the combined multi-lens camera so iOS can switch to the ultra-wide lens.
  2. Flash during a scan. The plugin has no such feature. The patch adds a set_torch command that turns on the flash for the camera already used by the scan. The flash turns off when the scan ends or is cancelled.

Status: both parts were checked by hand on one device. Nothing was measured. Description and status: PATCH.md.

Both apps were built in Release and tested with 10 scans per case, except the Tauri small QR at 30 cm, which failed on its only attempt. The scan timers start at slightly different points. In Tauri the time is measured in JavaScript, from the scan() call to the result, so it includes the bridge between the WebView and the native plugin. In Swift the time is measured in native code, from the start of camera setup to the decoded result. Both start after the camera permission is granted. The bridge adds little here: the medians differ by less than 10 ms.

Flash

Tauri (iOS): the first attempt used the separate tauri-plugin-torch plugin. It broke scanning: the image froze while the flash was on. The working version required changing the scan plugin itself, adding a set_torch command that controls the camera already used by the scan. No extra plugin is needed, but the patch must be maintained when the plugin updates.

Tauri (Android): not done. A separate flash plugin will probably not work either, so a custom change will be needed.

Swift (iOS): the torch is switched on the same camera device the scan session uses. No extra libraries. Checked by hand: the flash works and scanning continues. Apple's ready-made scanner (VisionKit DataScannerViewController) was tried first and dropped: it gives no access to its camera, and a separate torch froze the image, the same problem as in Tauri.
